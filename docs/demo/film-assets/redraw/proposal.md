# Proposal

## Why

Задача: {api.issue.key}. Победитель, не подтвердивший приз за 3 дня (R6), оставляет приз неразыгранным; организатору нужен повтор, который участники проверят так же, как исходный выбор (R4).

## What Changes

- Новый запрос API: повтор невостребованного приза на месте победителя - `POST /draws/:id/winners/:position/redraw`.
- Повтор продолжает ту же последовательность выбора из зерна розыгрыша (ADR-3, уточнение {decision.issue.key}): новый победитель - следующий кандидат среди ещё не выбранных (R5).
- Повтор доступен только для приза, не подтверждённого в срок (R6).

## Capabilities

### New Capabilities
- `redraw-unclaimed-prize`: повтор невостребованного приза из той же последовательности кандидатов.

### Modified Capabilities

## Impact

API розыгрыша (`api/src/draws`, `api/src/domain/rules.ts`); правила R4, R5, R6; ADR-3. Экран повтора в веб-приложении - отдельная задача.

## Критерии успеха

- Повтор после срока подтверждения выбирает следующего кандидата, и пересчёт из опубликованного зерна даёт того же победителя.
- До срока подтверждения и для подтверждённого приза повтор отклоняется, победитель не меняется.

## Вне рамок

- Экран повтора в веб-приложении.
- Новое зерно или выбор без продолжения последовательности - противоречит ADR-3.
