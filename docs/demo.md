# Сценарий демо: фабрика ПО на ИИ

Показ на 40 минут для команды заказной разработки. Сюжет - одна новая фича todo list ("редактирование текста задачи") проходит весь путь: замысел, спецификация, приёмочные сценарии, разработка агентом, проверки и ворота ИИ, слияние человеком, выкладка, эксплуатация, база знаний и учёт. Ведущий играет человека: пишет спецификацию со своим Claude Code в отдельном чате, ставит метки, читает решения ворот и сливает.

Главные мысли показа:
- агенты делают работу, человек решает: метка на задаче, решение на воротах, слияние;
- исполнитель сменный: Claude Code, Codex, OpenCode - строкой в настройках; судьи - модели другого семейства;
- качество держат детерминированные проверки и ворота ИИ, а не доверие к модели; узкое место - проверки, а не написание кода;
- знание живёт в git, база знаний отвечает с цитатами и сама ищет расхождения;
- всё измеряется с первого дня: цена, время по участкам, первая попытка, выкладки.

## Ход показа

### 1. Карта фабрики - 2 мин

Показать цепочку и сказать, где человек:

```
замысел -> спецификация (Claude) -> приёмочные сценарии (Codex) -> задачи
        -> метка человека -> агент в песочнице (Codex) -> PR от бота
        -> проверки: тесты, типы, сценарии, мутации, секреты, зависимости, SAST
        -> ворота ИИ: судьи Claude Opus и Sonnet, балл, круг доработки
        -> слияние человеком -> выкладка сама: сборка, Trivy, проверка здоровья, откат
        -> эксплуатация: сбои и ошибки сами заводят задачи
        -> база знаний: ответы с цитатами, сверка расхождений; учёт по каждому шагу
```

Открыть `.factory/config.yml` в репозитории todo: роли (spec - Claude Opus, tests - Codex, dev - Codex), судьи, пороги ворот. "Сменить исполнителя - одна строка".

### 2. Замысел -> спецификация: человек со своим Claude Code - 8 мин

Замысел, требования и архитектура - работа человека с агентом (HITL): ведущий пишет спецификацию в отдельном чате своего Claude Code, фабрика подхватывает её после слияния. Автономный вариант (агент спецификации по метке `agent:spec`) - `scripts/new-task.sh todo "Спецификация: редактирование задачи" examples/tasks/demo-edit-spec.md agent:spec`.

**Заранее** (за час): рабочая копия и, по желанию, поиск базы знаний в Claude Code:

```sh
mkdir -p ~/demo && cd ~/demo
git -c credential.helper='cache --timeout=14400' clone http://factory-admin@127.0.0.1:3000/factory-admin/todo.git
cd todo && git config credential.helper 'cache --timeout=14400'
claude mcp add --transport http kb http://127.0.0.1:8300/mcp --header "Authorization: Bearer $(cat ~/DEV/GITS/ai-factory/.state/kb/mcp.token)"
```

Пароль `factory-admin` - в `~/DEV/GITS/ai-factory/.state/admin.password` (`clip.exe < ...` копирует его в буфер, не выводя на экран).

**На показе:** в отдельном окне Claude Code в `~/demo/todo` попросить:

> Помоги мне как аналитику описать изменение OpenSpec `add-todo-edit` навыком openspec-propose: редактирование текста задачи в todo list. Исходный замысел - в файле ~/DEV/GITS/ai-factory/examples/tasks/demo-edit-spec.md. Сначала задай мне 2-3 уточняющих вопроса. Пункт в tasks.md - 4.1 (метки сценариев сквозные по проекту). Если нужен контекст проекта - ищи в базе знаний kb (search_indexed_documents с agent "Assistant"). Проверь `npx -y @fission-ai/openspec@1.13.2 validate add-todo-edit --strict`. Код не трогай.

Ответить на вопросы агента, прочитать требования и ADR, попросить поправить, если нужно. Затем:

> Создай ветку spec/add-todo-edit, закоммить изменение и отправь её в origin.

В Forgejo открыть PR из ветки `spec/add-todo-edit`, дождаться зелёных проверок, слить. Через минуту бот сам заводит задачу "[add-todo-edit 4.1] ..." (мост "спецификация -> задачи").

**Сказать:** "Требования и архитектуру человек пишет вместе со своим агентом и утверждает слиянием. Дальше работает фабрика: сценарии, код и ревью делают разные модели."

**Если затянулось:** показать слитую спецификацию todo (`openspec/changes/archive/2026-10-12-add-todo-list/`) и задачи #8-#14, которые бот завёл из неё.

### 4. Разработка агентом и ворота ИИ - 12 мин

**Действие человека:** в Forgejo на задаче "[add-todo-edit 4.1] ..." поставить метку `agent` мышкой. Это и есть решение "брать в работу".

**Что видно:**
- через 2-4 минуты - PR "agent: ..." от бота: код, модульные тесты, тело PR с исполнителем, моделью и временем;
- проверки PR: `test`, `types`, `acceptance` (теперь `@task-4.1` по-настоящему), `mutation` (StrykerJS, до 7 мин), `secrets`, `deps`, `sast`;
- последним - `gate`: судьи Claude Opus и Sonnet ставят балл; статус коммита `factory / ai-gate` с оценками - для человека; находки - комментарием в PR; балл агенту не показывается.

**Пока идут проверки (около 8 мин):** показать разделы 5 и 7.

**Исход ворот:**
- "готово для человека" - прочитать дифф и находки, слить;
- "на доработке" - показать, как метка снова ставится сама и агент дорабатывает в той же ветке по замечаниям;
- "решение человека" - написать решение комментарием в PR и запустить доработку: `scripts/rework.sh todo <номер задачи>`.

**Сказать:** "Агент пишет пункт за 2-4 минуты, остальное время - проверки. Модели не доверяем: доверяем тестам, мутациям, сканерам и судьям другой модели. Человек - на последнем шаге."

**Если затянулось:** открыть PR #20 (первая попытка, оценки 90 и 91) и PR #23 (доработка по решению человека).

**Сказать:** "Мост замыкает цикл: ошибка на стенде становится задачей, задача с меткой - работой агента."


**Что видно:** ответ со ссылками: ADR-10 в `design.md` (строка 85) и решение человека в PR #18. Тот же вопрос - в чате базы (:8300). Через пару минут после слияния новой спецификации - вопрос про неё:

```sh
scripts/kb-ask.sh "Почему редактирование задачи сделано формой на той же странице?"
```

**Портал (:8400):** спецификация, решения и вики из git; у каждой страницы - ссылка на источник.

**Сказать:** "Утверждённое знание - в git, база - индекс и сверка. Расхождение не исправляется молча: задача уходит хозяину сведений."

**Если затянулось:** задачи #33 и #34.

Модель ответов базы переключается одной командой: `scripts/kb-model.sh kb-claude-cli | kb-claude-api | kb-openrouter` (подписка через `claude -p`, API-кредиты Max, OpenRouter).

### 7. Учёт - 3 мин

```sh
scripts/factory-report.sh todo
```

**Что видно:** четыре числа - цена принятого изменения, время от задачи до стенда по участкам, доля слитых с первой попытки по исполнителю и модели, DORA выкладок - и строка новой задачи в таблице. У подписок цена теневая, по прайсу API.

**Сказать:** "Каждый запрос модели помечен задачей, поэтому известна цена каждого изменения и видно, какая модель работает лучше на наших задачах."

### 8. Выкладка и откат - 3 мин

После слияния PR разработки служба выкладки сама: собирает образ по рецепту фабрики, проверяет его Trivy, поднимает, проверяет здоровье и ставит статус `deploy / stand` на коммит.

- открыть :8081 - отредактировать задачу;
- `scripts/rollback.sh todo` - вернуть прошлую версию (редактирования нет), `scripts/rollback.sh todo status`, затем выложить снова: `scripts/deploy.sh todo`.

### 9. Безопасность и итог - 4 мин

Коротко и по экрану README, раздел "Решения безопасности":
- агент работает в песочнице без токенов записи; PR открывает отдельное задание без ключа модели;
- задания выходят в интернет только через прокси со списком адресов;
- агент не может изменить процессные файлы (`.forgejo/`, `.factory/`), спецификацию и приёмочные сценарии; сканеры не слушают файлы-исключения из PR;
- выкладывает служба фабрики по своему рецепту, задания Docker не получают.

Итог - три числа со стенда: изменение стоит в медиане 0,21 доллара, проходит путь от задачи до стенда за 17 минут, 70% изменений слиты с первой попытки (у Codex - 80%).
