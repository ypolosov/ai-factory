Дополни и заархивируй изменение OpenSpec `add-todo-list`: все его пункты слиты в main.

- В требования изменения добавь защиту изменяющих запросов от чужих сайтов (решение человека в PR пункта 1.2): `POST` с заголовком `Origin`, хост которого после нормализации (регистр, порт по умолчанию) не совпадает с заголовком `Host`, получает ответ 403, список не меняется; запросы без `Origin` обрабатываются как прежде. Сценарии: чужой `Origin` - 403; свой `Origin` - обычный ответ; без `Origin` - обычный ответ; `Host` с другим регистром или портом по умолчанию - обычный ответ.
- В design.md - решение (ADR): проверка `Origin` вместо токенов CSRF, почему этого достаточно для страницы без входа и без cookie.
- В test-plan.md - эти сценарии с меткой `@task-1.2`.
- Отметь пункты tasks.md выполненными, проверь `openspec validate add-todo-list --strict` и заархивируй изменение (`openspec archive add-todo-list --yes`): требования переходят в `openspec/specs/`.
